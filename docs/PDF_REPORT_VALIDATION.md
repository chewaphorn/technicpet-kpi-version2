# การตรวจสอบ PDF ให้ตรงกับ Dashboard

แก้ใน Version2 โดยให้ Dashboard, รายงานภาพรวม และ PDF ใช้การรวมบิลและการคำนวณร่วมกันใน `src/utils/salesReportMetrics.ts` และ `src/utils/logisticsReportMetrics.ts`

สาเหตุที่แก้ไข:

- พรีวิวเคยรีเซ็ตแผนกจาก props เมื่อวันที่ของข้อมูลเปลี่ยนหลังสลับแท็บ ทำให้กลับไปแผนกเดิม ตอนนี้เปิดพรีวิวแต่ละครั้งเป็น session ใหม่ และเก็บข้อมูล ณ ตอนเปิดไว้ตลอด session
- ปุ่ม Export ฝ่ายขายและภาพรวมไม่ได้ส่งช่วงวันที่ที่ใช้อยู่ และ App เคยทิ้งช่วงวันที่เมื่อเลือกเพียงขอบเขตด้านเดียว ตอนนี้ส่งวันที่และตัวกรองตามหน้าต้นทาง รวมทั้งประเภทบิล สถานะ คำค้น และทะเบียนรถ
- หน้าส่งออกรวมเคยใช้ช่วงวันที่ของฝ่ายขายกับทุกแผนก ตอนนี้เลือกวันที่จากข้อมูลของแผนกนั้น
- สูตร PDF เคยแยกจาก Dashboard รวมถึงค่าเป้าหมายยอดขายและผลงานพนักงานที่สร้างขึ้นเอง ตอนนี้ใช้สูตรเดียวกันและอ่านเป้าหมายจากการตั้งค่าชุดเดียวกัน
- ไม่ย้อนกลับไปใช้ยอดสรุปเก่าเมื่อไม่พบข้อมูลตามตัวกรอง จำนวนบิลขนส่งแสดงหน่วยบิล ไม่ใช่เที่ยวรถ และข้อมูลว่างไม่แสดงความสำเร็จ 100%
- การรวมบิลขนส่งซ้ำไม่แก้จำนวนสินค้าในข้อมูลต้นฉบับ และไม่สร้างค่า Lead Time 1 วันเมื่อไม่มีข้อมูลคำนวณ
- PDF แสดง Min/Mean/Max และการแจกแจง Lead Time จากชุดคำนวณเดียวกับ Dashboard คลังและขนส่ง

การทดสอบ:

```powershell
npm.cmd run typecheck
npm.cmd run build
npm.cmd run test:reports
```

Browser regression ใช้ Edge แบบ headless และข้อมูลจำลองในเครื่อง ไม่เชื่อม Firebase หรือดึงข้อมูล Google Sheets ใช้ permission predicates จริงจาก `authControl.ts` ส่วนการสร้าง PDF ใช้ `exportElementToPDF` จริงและเปลี่ยนเฉพาะการบันทึกไฟล์ให้ลง `test-results/pdf-reports/`

ครอบคลุมการสลับแผนกหลายรอบ ช่วงวันที่แต่ละแผนกต่างกัน การเปิดใหม่ การเปลี่ยนข้อมูลเบื้องหลัง ช่วงวันที่ด้านเดียว ข้อมูลว่าง บิลซ้ำ วันที่ไม่ครบ ตัวกรอง เป้าหมายที่เปลี่ยนจากค่าเริ่มต้น ปุ่ม Export ของแต่ละหน้าจริง สิทธิ์ผู้ใช้ และการสร้าง PDF A4 ทั้ง 4 รายงาน

ไฟล์ `test-results/pdf-reports/results.json` เก็บผลตรวจล่าสุดและจำนวนหน้า PDF การทดสอบนี้ยืนยันการทำงานกับข้อมูลจำลอง ไม่ได้ยืนยันความครบถ้วนของข้อมูลสดใน Google Sheets ขององค์กร
